# TreeROI Frontend

The TreeROI frontend is the interactive web dashboard for the TreeROI urban
heat resilience application.

It allows a user to select an area on a map, configure an analysis, submit it
to the TreeROI backend, and view the resulting heatmap information, prioritized
tiles, TreeROI scores, diagnostics, and recommended interventions.

The frontend is built with **React** and **Vite**.

---

## Features

- Interactive OpenStreetMap-based map
- Polygon-based area selection
- Analysis date and time selection
- Heatmap granularity selection
- Number of priority tiles selection
- TreeROI analysis submission
- Prioritized tile results
- TreeROI scores and priority levels
- Tile-level diagnostics
- Recommended interventions
- Mock-data mode for interface testing without using API credits

> **Current scope:** Area selection is intentionally limited to polygons.
> Circle selection and file uploads are not currently included.

## Environment Configuration

The frontend communicates with the TreeROI backend through the following
Vite environment variable:

```VITE_API_BASE_URL```

# Local Development

Create a .env file inside the frontend directory:

```VITE_API_BASE_URL=http://127.0.0.1:8000```

This points the frontend to a locally running TreeROI backend.

# Production

For the deployed application, VITE_API_BASE_URL should point to the
deployed TreeROI backend.

Example:

```VITE_API_BASE_URL=https://treeroibackend-production.up.railway.app```

The API path should not be included in this variable.

Use:

```https://treeroibackend-production.up.railway.app```

rather than:

```https://treeroibackend-production.up.railway.app/api/analysis```

The frontend adds /api/analysis when submitting an analysis.

Vite environment variables are embedded during the frontend build. After
changing VITE_API_BASE_URL, rebuild and redeploy the frontend.

## Using the Application

# 1. Select an Area
Use the polygon drawing tool in the upper-right corner of the map.
Draw a polygon around the urban area that should be analyzed.

# 2. Configure the Analysis
Provide:

Analysis date
Analysis time
Heatmap granularity
Number of top tiles to analyze

# 3. Run the Analysis
Click Analyze Area.
The frontend sends the selected polygon and analysis parameters to:

```POST /api/analysis```

# 4. View the Results
The dashboard displays the analysis returned by the backend, including:

Heatmap information
Prioritized tiles
TreeROI scores
Priority levels
Tile diagnostics
Recommended interventions

## API Request

The frontend sends a request with the following structure:

```python
{
  "polygon_aoi": {
    "type": "FeatureCollection",
    "features": []
  },
  "date": "YYYY-MM-DD",
  "time": "HH:MM",
  "granularity": 100,
  "top_n": 1
}
```
The polygon_aoi value contains the GeoJSON FeatureCollection generated by
the map drawing interface.

## Mock Data Mode

The frontend includes a mock-data mode for testing the dashboard without
sending requests to the backend.

Mock mode is controlled in:

```src/api.js```

Set:

```python
const USE_MOCK_DATA = true;
```
to enable mock mode.

In mock mode:

No backend request is sent.
No FortyGuard request is made.
No FortyGuard API credits are consumed.
The dashboard can be tested using predefined analysis results.

## For real analysis, set:

```python
const USE_MOCK_DATA = false;
```

## Backend Connection

The frontend does not communicate directly with FortyGuard.
The request flow is:

User
  │
  ▼
TreeROI Frontend
  │
  │ POST /api/analysis
  ▼
TreeROI Backend
  │
  ▼
FortyGuard
  │
  ▼
TreeROI Backend
  │
  │ Analysis response
  ▼
TreeROI Frontend
  │
  ▼
Dashboard

This keeps the FortyGuard API key on the backend rather than exposing it in
the browser.
